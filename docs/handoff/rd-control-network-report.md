# Задание для RD Control: `network_report` — потерянные, переехавшие и незарегистрированные принтеры

Направление: `printer-agent` → RD Control. Формат и правила — в
[docs/agent-collaboration.md](../agent-collaboration.md).

Контракт-владелец: [docs/contracts/agent-hub-v1.md](../contracts/agent-hub-v1.md),
раздел `network_report`, а также `settings.recovery.survey_interval_s`. Ломающих
изменений нет, `PROTOCOL_VERSION` остаётся `1`: новый тип сообщения агент → хаб и
одно новое необязательное поле настроек.

Продолжение [rd-control-printer-identity.md](rd-control-printer-identity.md).

---

## Зачем

25.09.2026 на loc-1 после перезапуска роутера все принтеры сменили адреса. Версия
с `device_id` вышла *после* этого, и агент ни разу не успел выучить идентификаторы.
Поэтому поиск по идентификатору ничего не нашёл, а оператор ничего не видел: агент
молча опрашивал пустые адреса.

Теперь агент:

- ищет и принтеры без выученного `device_id` — по имени устройства, из которого
  был сделан ключ (`K1C-B24E` → `k1c-b24e`); совпадение только точное и единственное;
- при каждом поиске опрашивает все протоколы, а раз в `survey_interval_s` (по
  умолчанию час) делает обзор сети, даже если ничего не потеряно;
- **сообщает хабу**, что нашёл, в новом сообщении `network_report`.

Прогон на живой сети loc-1 25.09.2026: k1-0942, k2plus-0ec5, k1c-b24e и k1-022d
переехали сами. Ender5 (ключ не совпадает с именем `Ender-5 Max-549B`) и
a1-mini-sancho (серийник нигде не отвечает) попали в `lost`. Два Bambu на `.47` и
`.50` и сам Ender-5 Max на `.49` пришли в `unregistered`.

## Что приходит на провод

```json
{ "type": "network_report", "payload": {
  "location_key": "loc-1", "scanned_at": "…", "networks": ["10.13.0.0/24"],
  "lost":         [ { "printer_key", "brand", "host", "device_id", "reason": "not_found|ambiguous", "detail"?, "offline_since"? } ],
  "moved":        [ { "printer_key", "old_host", "host" } ],
  "unregistered": [ { "host", "name", "model", "protocols": [ { "brand", "port", "device_id" } ] } ]
} }
```

Полная семантика — в контракте. Коротко:

- Сообщение описывает **состояние, а не событие**: каждое следующее заменяет
  предыдущее целиком, пустой список значит «нет». В outbox оно не хранится, `ack`
  на него не нужен.
- Приходит при изменении, после каждого `hello` и сразу, когда потерянный принтер
  снова ответил или незнакомца добавили в конфиг.
- `moved` — разовая новость: в следующем сообщении этого переезда уже не будет.
  Сам переезд, как и раньше, придёт ещё и как `inventory`.

## Что нужно от хаба

1. **Принимать тип `network_report`** (добавить в `AGENT_MESSAGE_TYPES`) и хранить
   последний отчёт по агенту. Сейчас хаб отвечает на него `unknown_message_type`:
   это безопасно (агент только пишет это в журнал), но оператор ничего не видит.
2. **Показывать `unregistered` на экране агента/площадки** как «найдены
   незарегистрированные принтеры»: адрес, имя, модель, протоколы. Если есть
   действие «добавить», пусть оно отправляет `settings_update` с полным
   `printers` (порядок действий — [docs/remote-settings-runbook.md](../remote-settings-runbook.md)).
   У `bambu` понадобится код доступа, которого нет в сети: его вводит человек.
   Серийник берётся из `protocols[].device_id`, при этом записывать его нужно
   **в верхнем регистре**, как он напечатан на принтере.
3. **Показывать `lost`** рядом со статусом принтера: «агент искал его в сети и не
   нашёл» (`not_found`) или «нашёл больше одного кандидата» (`ambiguous`, текст в
   `detail`). Это не то же самое, что просто `offline`.
4. **Показывать `moved`** в журнале событий площадки («k1c-b24e: 10.13.0.125 →
   10.13.0.46»).
5. В редакторе настроек не терять `recovery.survey_interval_s` (`0` — выключено).

## Порядок выкатки

Хаб можно обновлять в любой момент: агент уже шлёт сообщение, а старый хаб его
вежливо отклоняет. Поле `survey_interval_s` необязательное.

## Проверка

- Агент с этим изменением на loc-1: примерно через `after_offline_s` после запуска
  приходит `network_report` с тремя адресами в `unregistered` (`.47`, `.49`, `.50`)
  и, пока Ender5 и a1-mini-sancho не исправлены, с ними в `lost`.
- Добавить `.49` через `settings_update` → следующий `network_report` приходит без
  него, не дожидаясь следующего обзора.
