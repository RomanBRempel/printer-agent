# Задание для RD Control: чтение журнала агента — `log_request` / `log`

Направление: `printer-agent` → RD Control. Формат и правила — в
[docs/agent-collaboration.md](../agent-collaboration.md).

Контракт-владелец: [docs/contracts/agent-hub-v1.md](../contracts/agent-hub-v1.md),
разделы `log` и `log_request`. Ломающих изменений нет, `PROTOCOL_VERSION`
остаётся `1`: добавляются два типа сообщений. Агент готов с `0.1.0a26`.

---

## Зачем

Каждый разбор на площадке за эту неделю упирался в одно и то же: ответ лежит в
`agent.log`, а `agent.log` — на компьютере, у которого никто не стоит. Файл
приходилось пересылать вручную, и половина диагнозов ставилась по обрезанному
скриншоту.

## Что появилось на проводе

**Хаб → агент, `log_request`** — все поля необязательные:

```json
{ "file": "agent.log", "lines": 500, "level": "WARNING" }
```

**Агент → хаб, `log`:**

```json
{
  "location_key": "loc-001",
  "agent_version": "0.1.0a26",
  "request_msg_id": "req-1",
  "file": "agent.log",
  "files": [
    { "name": "agent.log", "size_bytes": 725011, "modified": "2026-08-19T12:04:11Z" },
    { "name": "agent.log.2026-08-18", "size_bytes": 2097081, "modified": "2026-08-19T00:00:02Z" }
  ],
  "lines": ["ts=… level=WARNING logger=… message=…"],
  "truncated": true
}
```

`command_id` нет и `command_result` не будет — это запрос состояния, как
`inventory_request` и `settings_request`, и ни одного принтера он не трогает.

## Что важно знать при реализации

**Ответ ограничен, и это не настройка.** Максимум 2000 строк и 256 КБ, что
раньше кончится. Больше агент не пришлёт, сколько ни попроси: сообщение едет по
той же сессии, что телеметрия и команды, а журнал — мегабайты. `truncated: true`
значит «за этим есть ещё», а не «ответ испорчен».

**`lines` — это хвост, старые строки первыми.** Печатать можно как есть, не
переворачивая.

**Фильтр по уровню применяется до счётчика.** `{"lines": 200, "level": "WARNING"}`
вернёт до 200 предупреждений, а не предупреждения среди последних 200 строк. На
болтливом агенте разница между полезным ответом и пустой рамкой. Строки без
уровня (тело трассировки) остаются всегда — исключение без тела бесполезно.

**`files` — для выбора, а не для украшения.** Ротация теперь суточная, десять
дней; имя вчерашнего файла хаб угадывать не должен, оно приезжает в списке.

**`file` проверяется как путь.** Хаб называет путь на чужой машине, поэтому
принимаются только простые имена файлов из каталога журналов. Всё с разделителем
внутри отвергается — ответ придёт с полем `error` и без `lines`. Это не ошибка
сессии, показать надо текст.

**Секреты вычищены, но полагаться на это как на единственную защиту нельзя.**
Агент заменяет известные значения (`agent_token`, коды доступа принтеров) на
`***`. Со стороны хаба всё равно стоит считать журнал чувствительным: он
показывает адреса принтеров, имена файлов и внутреннее устройство площадки.
**Доступ к просмотру — только тем, кому положено видеть настройки агента.**

## Что сделать

1. Принимать `log`, показывать `lines` моноширинно, `files` — выпадающим
   списком, `truncated` — пометкой «показано не всё».
2. Слать `log_request` по кнопке на карточке агента. Периодически не слать: это
   ручной инструмент разбора, а не поток.
3. Дать в интерфейсе выбор уровня. По умолчанию `WARNING` — при разборе
   поломки ищут именно его, а `INFO` на активной площадке забивает экран
   телеметрией.
4. Считать молчание нормой: агент старее `0.1.0a26` не знает этот тип и не
   ответит. По таймауту сказать «этот агент старее», а не «агент сбоит».
5. Закрыть просмотр правами.

## Порядок выкатки

Агент уже умеет и молчит, пока не спросят, так что хаб может начинать в любой
момент. Проверьте только, что неизвестный тип `log` в приёмнике не роняет
сессию, если хаб выкатите раньше, чем прочитаете этот файл.

## Приёмка

1. Кнопка на карточке агента возвращает последние строки журнала.
2. `level: "ERROR"` на активной площадке возвращает ошибки, а не пустоту.
3. Запрос `"file": "../agent.yaml"` возвращает `error` и ничего больше.
4. В выдаче нет ни кода доступа принтера, ни токена агента — вместо них `***`.

## Чего я не менял и почему

- Ничего в репозитории RD Control.
- Не сделал поток журнала в реальном времени: это ручной инструмент разбора, а
  постоянный поток — второй канал телеметрии, которого никто не просил.
- Не дал скачивать файл целиком. Хвост с потолком отвечает на вопрос «что
  сейчас сломалось»; на «пришлите весь журнал за вторник» отвечает файл с
  машины, и делать из сессии агента файловый сервер ради этого не стоит.
