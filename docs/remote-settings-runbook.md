# Удалённая настройка агента: порядок работы

Как менять настройки площадки из хаба, не подходя к машине. Формы сообщений — в
[contracts/agent-hub-v1.md](contracts/agent-hub-v1.md), задание для хаба — в
[handoff/rd-control-remote-settings.md](handoff/rd-control-remote-settings.md).
Здесь только последовательность действий и то, обо что об это спотыкаются.

Требуется агент **0.1.0a19** или новее.

---

## Правило, которое стоит прочитать до первой правки

**`printers` заменяет список целиком.** Другого способа сказать «этого принтера
больше нет» на проводе не существует, поэтому присутствие ключа означает «вот
весь состав». Правка одного принтера коротким списком удаляет всех остальных:

```json
{ "command_id": "c1", "settings": { "printers": [ { "key": "jekson-h2d", … } ] } }
```

→ на площадке остаётся **один** принтер. Проверено, это не теория.

Отсюда порядок работы: **сначала прочитать, потом изменить прочитанное, потом
отправить целиком.** Никогда не собирать список из головы и не брать его из
`hello`, который хаб запомнил когда-то.

---

## Шаг 1. Прочитать текущее состояние

Хаб → агент:

```json
{ "v": 1, "type": "settings_request", "msg_id": "req-1", "ts": "…", "payload": {} }
```

Агент → хаб: `settings` с `request_msg_id: "req-1"`, где `settings.printers` —
полный состав, а секреты заменены на `__redacted__`:

```json
{
  "settings": {
    "telemetry_interval_s": 5,
    "heartbeat_interval_s": 15,
    "command_reconnect_backoff_s": { "min": 1, "max": 60 },
    "outbox": { "max_events": 5000 },
    "print_files": { "max_age_h": 72, "max_total_mb": 2048 },
    "updates": { "feed_url": "https://…", "auto_update": true, "check_on_startup": true, "check_interval_h": 24 },
    "printers": [
      { "key": "k2plus-0ec5", "brand": "moonraker", "host": "10.13.0.130", "port": 7125 },
      { "key": "a1-mini-sancho", "brand": "bambu", "host": "10.13.0.132", "port": 8883,
        "credentials": { "serial": "0309DA4B0803132", "access_code": "__redacted__" } },
      { "key": "jekson-h2d", "brand": "bambu", "host": "10.13.0.158", "port": 8883,
        "credentials": { "serial": "…", "access_code": "__redacted__" } }
    ]
  },
  "readonly": {
    "hub_url": "…/api/printers/agent",
    "outbox": { "database_path": "C:\\ProgramData\\printer-agent\\data\\outbox.sqlite3" }
  }
}
```

`readonly` — для показа, не для правки. `agent_token` не приезжает вовсе.

## Шаг 2. Изменить прочитанное

Взять `settings.printers` **как есть**, поправить нужные поля, остальные записи
оставить нетронутыми — вместе с их `"access_code": "__redacted__"`, который
агент поймёт как «оставь свой».

## Шаг 3. Отправить

```json
{
  "v": 1, "type": "settings_update", "msg_id": "upd-1", "ts": "…",
  "payload": { "command_id": "c1", "settings": { "printers": [ …весь список… ] } }
}
```

Ответ — `command_result` с **пустым `printer_key`** (команда про агента, а не про
принтер) и разбором по полям:

```json
{
  "command_id": "c1", "printer_key": "", "status": "done", "error_text": "",
  "response": {
    "applied": ["printers[8]"],
    "kept_local": ["printers.a1-mini-sancho.credentials.access_code"],
    "rejected": [],
    "missing": [],
    "restart_required": false
  }
}
```

## Шаг 4. Дождаться подтверждения делом

`done` означает «принято», а не «действует». Агент пишет `agent.yaml`, а его
обычный перечитыватель конфига в течение одного `telemetry_interval_s` (5 с)
пересобирает адаптеры изменившихся принтеров и **сам присылает `inventory`**.
Вот он и есть подтверждение. Перезапуск службы не нужен.

---

## Значения полей

| В сообщении | Смысл |
|---|---|
| ключ отсутствует | оставить как есть |
| `"__redacted__"` | оставить как есть (это то, что агент сам и прислал) |
| `""` | оставить как есть |
| `null` | **очистить** — единственный способ отозвать учётку удалённо |
| непустое значение | записать |

## Что агент откажется менять

`hub_url`, `agent_token`, `location_key`, `outbox.database_path`. Они называют
сессию и открытую базу; ошибка в них оставила бы агента без канала, которым его
можно чинить. Приезжают обратно в `rejected`, а не выбрасываются молча. Правка
из одних только этих полей даёт `status: "failed"` — «принято» на изменение,
которого не было, хуже отказа.

## Когда ничего не записывается

Объединённый конфиг проверяется **до** записи. Если он не проходит проверку —
неизвестный `brand`, пустой `host` — на диск не попадает ничего, ответ `failed`,
а `error_text` перечисляет причины. Форма в хабе не может снять площадку с эфира.

---

## Пример: починка H2D от 18.08.2026

H2D отвечал `0500-4002` («неподдерживаемый путь») на команду печати, потому что
по умолчанию адрес — `file:///sdcard/`, а эта модель ждёт корень FTP. Заодно на
принтере после включения LAN Only Mode сменился код доступа.

В прочитанном списке правится **одна запись**, остальные едут без изменений:

```json
{
  "key": "jekson-h2d", "brand": "bambu", "host": "10.13.0.158", "port": 8883,
  "credentials": {
    "serial": "…",
    "access_code": "6d5af2fc",
    "print_url_prefix": "file:///"
  }
}
```

`print_url_prefix` — не секрет: он виден в `settings` открытым текстом и его
можно показывать оператору. `serial` тоже не секрет — он опознаёт принтер, а не
даёт к нему доступ.

Проверка: в течение 5 секунд приходит `inventory`, H2D перестаёт быть `offline`,
следующая заявка печатается. Если снова `0500-4002` — префикс не тот; если
`0500-4003` — префикс верный, а спотыкается уже плита в файле, и это лечится
обновлением агента до 0.1.0a22 или новее.

## Проверка перед боем

Прогнать на одной площадке в таком порядке:

1. `settings_request` → в ответе нет ни одного настоящего секрета, а заданные
   видны как `__redacted__`.
2. Сохранить форму, ничего не поменяв → `done`, коды доступа на месте, ни один
   принтер не исчез.
3. Поменять `telemetry_interval_s` → `done`, поле в `applied`, `agent.yaml`
   изменился.
4. Прислать `hub_url` → `failed`, поле в `rejected`, агент на прежнем хабе.
5. Добавить принтер → в течение цикла телеметрии приходит `inventory`, принтер
   доступен для закрепления.

Пункт 2 — самый важный: именно он ловит и потерю состава, и затирание секретов
маркером.
